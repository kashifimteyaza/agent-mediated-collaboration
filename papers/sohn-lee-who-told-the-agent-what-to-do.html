§ Position provocation · Nobody Did This, CSCW 2026

Who Told the Agent What to Do? AI Instruction Files and Accountability Before Code Review

Donghyun Sohn · Harin Lee · Northwestern University, Evanston, IL, USA; Ewha Womans University, Seoul, Republic of Korea

Download PDF SSRN All accepted papers
§ Abstract

Position paper

Developers increasingly use repository files such as CLAUDE.md, AGENTS.md, and .cursor/rules to guide AI coding agents before they produce code. These files tell the agent what to change, what to leave alone, which part of the project to trust, and even how to describe its own work. Code review usually starts later, once a patch already exists. At that point, a reviewer may see the diff and an “AI-assisted” note while the instructions available to the agent remain outside the review. We study this gap with 4,664 such files from 4,485 public GitHub repositories. In a stratified sample of 499 pairs of an instruction file and the same repository’s README, a classifier found both behavioral constraints and project judgments absent from the README in 88.2% of pairs, and a stricter hand check confirmed both in 57%. Only 16.7% of READMEs point to the instruction file by name. Even counting broader signals such as a mention of Claude, Cursor, or a coding agent, only 33.8% do. For most repositories, a person reading the README would not know that an agent-facing instruction layer exists. We argue that accountability for AI-assisted work should begin before the patch by making the instructions that precede it reviewable. This shifts the question from whether AI was used to what the agent was told, whether those instructions can be reviewed and challenged, and how the resulting contribution is credited. We treat this as an upstream condition for accountability rather than evidence that work is already being misattributed.

Both authors contributed equally to this work.
